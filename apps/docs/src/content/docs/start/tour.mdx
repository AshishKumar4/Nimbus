This is a single walk through one session, in the order you'd naturally
discover the machine. Every block below is copy-paste-runnable in a
[session of your own](/docs/start/boot/).

## 1. It's a real shell

Pipes, redirects, and 60+ Unix commands, backed by a structured
lexer, parser, and interpreter rather than regex string rewriting.

```bash
$ printf 'cherry\napple\nbanana\n' > fruits.txt
$ sort fruits.txt | head -2
apple
banana
$ wc -l fruits.txt
3 fruits.txt
```

More in [Terminal & shell](/docs/machine/terminal/).

## 2. The disk persists

Everything you write lands on a 10 GB SQLite-backed filesystem that survives
reconnects, hibernation, and Durable Object eviction. Close the tab, come
back tomorrow, and `fruits.txt` is still there. The URL is the session:
share it and a teammate joins the same filesystem. (On deployments that
enforce auth, including the hosted demo, joining also needs a valid attach
token — [tokens & auth](/docs/sdk/tokens/).)

More in [The disk](/docs/machine/disk/).

## 3. Real toolchains, not stubs

`node` and `bun` run on the workerd `nodejs_compat` runtime, the same V8
your Workers run on. `python` is Pyodide-compiled CPython 3.13. `ruby` is
ruby.wasm 3.3. And `clang` is a real LLVM toolchain that compiles C to
`wasm32-wasi-nimbus` inside the session:

```bash
$ cat > hello.c <<'EOF'
#include <stdio.h>
int main(void) { printf("hello from clang on the edge\n"); return 0; }
EOF
$ clang hello.c -o hello.wasm
$ ./hello.wasm
hello from clang on the edge
```

More in [Toolchains](/docs/machine/toolchains/).

## 4. Real package managers

`npm install` talks to the live registry, with a cross-session cache that
makes warm installs 9–16× faster than cold. `pip` and `gem` handle pure
packages, and native ones fail early with an ABI diagnostic that says why
(both are alpha).

```bash
npm install zod        # ~6 s on a cold session
npx cowsay hello       # npx with auto-install fallback
```

More in [Package managers](/docs/machine/packages/).

## 5. Real git

`git clone` over HTTPS runs in a dedicated engine facet with a chunked
checkout engine. facebook/react (7,300 files) lands in about 28 s, and
84,000-file worktrees materialize through bounded continuation.

```bash
git clone https://github.com/AshishKumar4/Markflow
cd Markflow && npm install && npm run dev
```

More in [Git](/docs/machine/git/).

## 6. Servers, loopback, and previews

Start a server and it becomes a resident process in its own isolate. Other
processes reach it over the session's loopback network, and the browser gets
a live preview tab:

```bash
$ cat > server.js <<'EOF'
const http = require('http');
http.createServer((req, res) => res.end('ok from another isolate')).listen(3000, () => console.log('listening on 3000'));
EOF
$ node server.js
listening on 3000
$ curl http://127.0.0.1:3000/
ok from another isolate
```

That `curl` crossed an isolate boundary. The server runs in its own facet,
and the supervisor's port registry routed the request. The same path serves
the preview iframe, including full Vite HMR.

More in [The network](/docs/machine/network/) and
[Processes](/docs/machine/processes/).

## 7. The agent is already there

Every session includes an agent chat surface in the editor workspace,
running inside the same Durable Object. It shares your filesystem, shell,
processes, and previews. More in [The session agent](/docs/machine/agent/).
