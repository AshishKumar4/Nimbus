Before building this I looked hard at what already exists — microVM
sandboxes, container platforms, in-process stub filesystems — and each
one asks for a trade I didn't want.

<WhereItFits caption="Four substrates. Nimbus gives up native Linux software to get per-request boots, true scale-to-zero, and a disk that outlives the machine." />

MicroVMs and containers give you a real Linux kernel — Docker, apt,
native binaries. Nimbus can't run those and doesn't claim to. What I get
back: ~0.6 s boots with no warm pool, $0 idle, and a disk that survives
eviction. On Cloudflare's own network my sessions came up about 3× faster
than the container-based Sandbox SDK — 0.61 s vs 1.95 s sequential median
([methodology and caveats](/docs/fine-print/benchmarks/)).

[agentOS](https://agentos-sdk.dev) by Rivet is the closest cousin —
isolates plus WASM, SQLite persistence, Pyodide CPython — though we
converged independently from opposite ends. Theirs is an npm package
beside your backend that mounts a real container when WASM runs out.
Mine *is* the deployment, a Worker plus Durable Objects with a URL per
computer, and it stays purist; that's why the multi-isolate process work
exists. Their docs rule out `fs.watch`, so no watch-mode dev servers;
Vite HMR works here at 302 ms median.

Need Docker, native wheels, GPUs, or raw TCP listeners? Use something
else — the full "no" list is in
[the fine print](/docs/fine-print/capabilities/).
