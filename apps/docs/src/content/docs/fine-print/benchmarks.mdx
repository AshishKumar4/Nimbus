## Session create → first command

Measured 2026-07-16 with the ComputeSDK methodology: wall-clock
`sandbox.create()` plus first successful `runCommand('node -v')`,
5% trimmed, composite = 0.60·median + 0.25·P95 + 0.15·P99 × success
rate.

| Mode | N | Success | Median | P95 | P99 | Composite |
|---|---|---|---|---|---|---|
| Sequential | 100 | 100/100 | **0.61 s** | 0.82 s | 0.87 s | 93.0 |
| Staggered (200 ms) | 100 | 100/100 | **0.57 s** | 0.78 s | 0.92 s | 93.3 |
| Burst (simultaneous) | 100 | 100/100 | **1.15 s** | 1.68 s | 1.96 s | 86.0 |

These are honest per-request Durable Object boots — no warm pool. Phase
measurement (N=15) puts `create()`+`ready()` at 545 ms median and first
exec at 23 ms, so ~96% of TTI is session boot; once booted, exec
round-trips run ~20 ms. Across ~370 total sandboxes I saw one failure (a
DO storage timeout reset during a smoke iteration) — reported, not
hidden.

Caveats, plainly: I ran from a residential Linux client, so network RTT
to the edge is inside these numbers, and Nimbus is not on the official
ComputeSDK leaderboard — I ran the unmodified harness locally. Treat
cross-provider numbers directionally. The one same-platform comparison:
against Cloudflare's container-based Sandbox SDK (published leaderboard
data, 2026-07-13), Nimbus measured ~3× faster across the board — 0.61 s
vs 1.95 s sequential median, 1.15 s vs 4.05 s burst.

## Everyday operations

Measured against the live deployment, 2026-07:

| Operation | Wall time |
|---|---|
| `git clone` facebook/react (7,300 files) | ~28 s |
| `npm install` 611-package app (52,500 files, cold) | ~165 s |
| `npm install zod` (cold session) | ~6 s |
| `node -e 'console.log(...)'` (warm) | 102–152 ms |
| Vite hot reload | 302 ms median |

Cross-session caching gives 9–16× warm-vs-cold speedups on package
installs.

Numbers don't rot silently here: `tests/behavioral/perf-regression/`
asserts these thresholds on every deploy, and anyone can run the suite:

```bash
BASE=https://nimbus.ashishkumarsingh.com bun test:behavioral
```
