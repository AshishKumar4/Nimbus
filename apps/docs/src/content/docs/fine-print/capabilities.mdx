## The deliberate "no" list

I built Nimbus on Workers, Durable Objects, and WASM, not as a Linux VM. If
you need one of these missing parts, use a microVM or container sandbox
([where Nimbus fits](/docs/start/where-it-fits/)).

| Not supported | |
|---|---|
| Docker, apt, custom Linux images | no container substrate exists |
| Native Linux ELF execution | there is no ELF loader |
| Native platform CLI shards, manylinux wheels, native gems | fail before import with an exact ABI diagnostic |
| Raw public TCP listeners | inbound is HTTP(S) through session routes |
| Next.js dev server, `wrangler pages dev` | explicit limits today |
| GPUs | — |
| `wasi-threads` / `-pthread` | refused at link time, [by design](https://github.com/AshishKumar4/Nimbus/blob/main/docs/wasi-threads.md) |

## Known constraints

| Constraint | State |
|---|---|
| One active terminal owner per session | sequential reconnect/share preserves state |
| `node`/`bun` REPL declarations don't persist | workerd CSP; scripts unaffected; Python/Ruby REPLs fully stateful |
| 75,000+-object clones | index-pack CPU headroom in progress |
| git transport | HTTPS only, no SSH |
| opencode TUI | serve half boots and streams SSE; attach half renders frames on a thin memory margin, still hardening |
| Hosted demo | evaluation only — no SLA, may be reset, not for secrets |

I've verified Vite + React, the Cloudflare Vite Plugin,
single-file Workers, Workers with Static Assets, npm and git workflows,
Python and Ruby scripts, and clang. Astro, SvelteKit, and Remix use the Vite
path. Nuxt has Nitro caveats.

I move the chip line one way only: a behavioral probe must prove the
capability live. The rest stays on the
[research frontier](/docs/fine-print/research/).
