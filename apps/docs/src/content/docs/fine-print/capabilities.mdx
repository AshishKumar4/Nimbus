## The "no" list

Nimbus is built on Workers, Durable Objects, and WASM, not as a Linux VM. A
workload that needs one of these missing parts belongs on a microVM or
container sandbox ([where Nimbus fits](/docs/start/where-it-fits/)).

| Not supported | |
|---|---|
| Docker, apt, custom Linux images | no container substrate exists |
| Native Linux ELF execution | there is no ELF loader |
| Native platform CLI shards, manylinux wheels, native gems | fail before import with an exact ABI diagnostic |
| Raw public TCP listeners | inbound is HTTP(S) through session routes |
| Next.js dev server, `wrangler pages dev` | explicit limits today |
| GPUs | — |
| `wasi-threads` / `-pthread` | refused at link time ([design note](https://github.com/AshishKumar4/Nimbus/blob/main/docs/wasi-threads.md)) |

## Known constraints

| Constraint | State |
|---|---|
| One active terminal owner per session | sequential reconnect/share preserves state |
| `node`/`bun` REPL declarations don't persist | workerd CSP; scripts unaffected; Python/Ruby REPLs fully stateful |
| `util.inspect` and `console` output of what V8 alone can read | `util.inspect` and `console` run Node's own `inspect.js`. A promise's result, an iterator's or a WeakMap/WeakSet's entries, and a proxy's target and handler are read as values through workerd's inspect and formatted by `inspect.js`. A proxy among them is shown by its target and handler, but a program's code is never handed a rebuilt one: without `showProxy`, one whose target has a `util.inspect.custom` shows as `<unknown>` (Node calls that with the proxy as `this`), and a proxy inside it is shown by its innermost target without running its traps. A promise, iterator or collection whose own `Symbol.toStringTag` is a getter, whose class has its own `Symbol.hasInstance` or a `name` getter, or that has a proxy on its prototype chain, shows what it holds as `<unknown>` or `<items unknown>`: reading it would run that code again |
| Where an uncaught error was thrown | `node`'s report of an uncaught error is Node's: the file, line and caret, the error as `util.inspect` shows it, Node's version, the exit code. The place is read off the error's stack, since a Worker cannot read V8's message: an error a builtin throws, which Node places at a line of its own library, is reported without one; a thrown value that is not an error, an error thrown away from where it was made (`throw e`), or one whose stack was replaced, has no place, or the place it was made at |
| Argument errors of the builtins workerd provides (`zlib`, `crypto`, `buffer`, `url`, `path`, …) | they have Node's shape (its class, code and stack header), but in 416 measured calls their wording or code differs from Node's, they do not throw, or the function is missing (tests/fixtures/builtin-error-gaps.json). The methods of a `Buffer`, an `EventEmitter` or an `AsyncLocalStorage`, hot paths, keep workerd's shape |
| `process.emitWarning` | `--disable-warning` and `--redirect-warnings` are not read; `NODE_NO_WARNINGS=1` and `--no-warnings` in `NODE_OPTIONS` are |
| 75,000+-object clones | index-pack CPU headroom in progress |
| git transport | HTTPS only, no SSH |
| A native wasm binary's linear memory | 128 MiB. Past it `malloc` returns NULL and the program reports its own allocation failure, instead of the session dying without one |
| opencode TUI | serve half boots and streams SSE; attach half renders frames from a facet with its own memory envelope, still hardening |
| Stopping an app's server (`box.apps`, `nimbus app`) soon after it starts, then starting it again | the session can reset: sockets close and that start is lost; files and the app's storage are kept. A Cloudflare facet-storage defect: measured 1 in 3 restarts when stopped as soon as it answered, 1 in 36 after 1.5 s idle |
| Hosted demo | evaluation only; no SLA, may be reset, not for secrets |

Verified live: Vite + React, the Cloudflare Vite Plugin, single-file
Workers, Workers with Static Assets, npm and git workflows, Python and Ruby
scripts, and clang. Astro, SvelteKit, and Remix use the Vite path. Nuxt has
Nitro caveats.

A capability joins this list only after a behavioral probe proves it live.
Until then it stays on the [research page](/docs/fine-print/research/).
