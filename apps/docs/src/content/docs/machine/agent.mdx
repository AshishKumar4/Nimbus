title: The session agent
description: A chat surface living inside the same Durable Object as your terminal — same disk, same processes, same ports.
---

The agent in every session isn't bridged in from outside — it lives in
the same Durable Object as your terminal. Same filesystem, same shell,
same process table, same preview ports. When it edits a file your editor
sees the change; when it starts a server your preview tab opens.

It speaks the AI SDK over Workers AI's OpenAI-compatible endpoint,
optionally through an AI Gateway, and streams into the chat pane with
thinking state and tool calls rendered inline.

Who pays for inference is the one real decision:

- **User OAuth** — each user connects their own Cloudflare account
  (Authorization Code + PKCE) and spends their own Workers AI quota. The
  hosted demo works this way.
- **Owner token** — your API token pays for everyone.

Either way, user OAuth tokens never touch Durable Object storage. They
live only in encrypted `HttpOnly`, `Secure`, `SameSite=Lax` cookies
scoped to the session URL.

## Wiring OAuth into your deployment

In Cloudflare's **Create OAuth client** form: grant type
`Authorization Code`, token auth method `None`, redirect URL
`https://<your-host>/api/nimbus/oauth/callback`. Select only these
scopes — and not `Account API Gateway`, which is API Shield, not AI
Gateway:

| Scope ID | Why |
|---|---|
| `user-details.read` | Read the connected user's profile |
| `account-settings.read` | List the user's accounts |
| `ai.write` | Run Workers AI inference |
| `aig.run` | Only when `NIMBUS_AGENT_GATEWAY_ID` is set |

```jsonc
// wrangler.jsonc
{
  "vars": {
    "NIMBUS_CF_OAUTH_CLIENT_ID": "<oauth-client-id>",
    "NIMBUS_CF_OAUTH_SCOPES": "<scope-id-1> <scope-id-2>",
    "NIMBUS_AGENT_MODEL": "@cf/moonshotai/kimi-k2.6",
    "NIMBUS_AGENT_GATEWAY_ID": "default"
  }
}
```

```bash
npx wrangler secret put NIMBUS_AGENT_COOKIE_SECRET
```

For the owner-token path instead, set `NIMBUS_CLOUDFLARE_ACCOUNT_ID` in
vars and `NIMBUS_CLOUDFLARE_API_TOKEN` as a secret. Custom login flows
can build on the OAuth helpers exported from `@nimbus-sh/sdk/worker`
([configure the handler](/docs/sdk/handler/)).
