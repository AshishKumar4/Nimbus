---
title: Processes & servers
description: Every process gets its own isolate; the loopback network and port previews wire them into one machine.
---

```bash
$ cat > server.js <<'EOF'
require('http').createServer((req, res) => res.end('ok from another isolate')).listen(3000);
EOF
$ node server.js
listening on 3000
$ curl http://127.0.0.1:3000/
ok from another isolate
```

That `curl` crossed an isolate boundary. Every process here runs in its
own V8 isolate with its own 128 MiB — the platform cap, a segment rather
than a ceiling — and the supervisor's port registry wires them into one
machine. Start a server and it auto-promotes to a resident process:
keyed isolate, registered port, no flags.

Three process kinds. One-shots spawn, run, stream their writes back,
and exit. Residents survive across requests and own ports. Attached TTYs
are residents with an interactive tab
([terminal & shell](/docs/machine/terminal/), alpha). The process table
lives in the supervisor, so `ps` stays truthful even when the platform
evicts a facet — an unrehydratable process is marked dead with a reason,
never left a zombie. Logs are durable and bounded, and
`child_process.spawn`/`exec`/`execFile` work inside Node with real piped
stdio.

Ports become previews. When a process starts listening, its preview tab
opens and focuses. It's a real `Request`/`Response` path — that's why
Vite HMR works end to end (302 ms median) — and it streams: SSE ticks and
chunked bodies relay live, `curl` writes chunks as they arrive,
<kbd>Ctrl</kbd>+<kbd>C</kbd> cancels.

Outbound, `fetch` and Node's HTTP clients work everywhere, WASI binaries
get real TCP through `/dev/tcp/<host>/<port>`, and npm, pip, gem, and git
all ride it. Inbound is HTTP(S) through session routes only — the
platform offers no raw public TCP listeners.

Because loopback crosses isolates, one app can be several cooperating
processes — that's how opencode runs (alpha). `fork()` isn't a shipped
syscall yet; the mechanism is [proven live](/docs/fine-print/research/).
