`git clone` on Nimbus is real git over HTTPS — real packfiles from real
remotes — running in a dedicated **git engine facet** so that network fetch,
object indexing, and worktree checkout each get a fresh CPU budget.

```bash
git clone https://github.com/AshishKumar4/Markflow
cd Markflow && npm install && npm run dev
```

## Built for big repositories

Small repos are easy; the engineering is in the big ones. The chunked
checkout engine materializes large worktrees via **bounded continuation** —
the checkout is sliced into resumable chunks so no single phase can blow its
isolate's CPU budget:

| Repository | Measured |
|---|---|
| facebook/react (7,300 files) | ~28 s |
| 84,000-file worktrees | materialize via bounded continuation |

## Everyday workflows

Clone, branch, inspect, commit — the common workflows agents and humans
actually run:

```bash
git clone https://github.com/<org>/<repo>
git status
git log --oneline -5
git add -A && git commit -m "change"
```

The working tree lives on [the disk](/docs/machine/disk/) like everything
else — the editor sees it, `npm install` runs in it, and it persists across
sessions.

## Honest edges

- **HTTPS only.** No SSH transport.
- **Very large clones**: index-pack CPU headroom for 75,000+-object
  repositories (microsoft/TypeScript-class) is still in progress — the fetch
  can exceed a per-invocation CPU budget. This is on the
  [research frontier](/docs/fine-print/research/) list.
