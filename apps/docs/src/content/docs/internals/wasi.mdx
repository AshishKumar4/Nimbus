---
title: WASI & syscalls
description: 45 of 46 preview1 functions, JSPI-suspended sockets, and the gaps stated exactly.
---

Compiled binaries — `clang` output and any `wasm32-wasi` module you
bring — run on a hand-written `wasi_snapshot_preview1` host. **45 of the
46 functions are implemented.** The gap is `sock_accept`: preview1 has no
inbound-socket story (`sock_open`/`bind`/`listen` don't exist in the
spec; every serious host fills that with an extension), and Nimbus's
extension is designed but not shipped.

The parts I'm pleased with:

- Blocking I/O actually blocks. Socket calls and `poll_oneoff` are
  wrapped in `WebAssembly.Suspending`, and `_start` runs under
  `WebAssembly.promising`, so the module suspends on I/O like a real
  syscall — feature-detected, with a fallback.
- Outbound TCP is a synthetic path: `path_open('/dev/tcp/<host>/<port>')`
  opens a real socket via `cloudflare:sockets`, with documented
  half-close semantics. `poll_oneoff` handles fd, clock, and socket
  subscriptions, mixed.
- The petty POSIX details hold up: `O_NOFOLLOW` and `O_APPEND` honored,
  symlinks survive `path_rename`, and `read(2)` on a socket fd routes
  correctly — wasi-libc maps `read` to `fd_read` for *all* fds, and the
  shim handles it.

Programs see the ABI they're on — `NIMBUS_ABI=wasm32-wasi-nimbus`,
emitted by the in-session clang and used by the runtime catalog to
classify artifacts. A file with WASM magic (or a persisted exec bit)
dispatches through the WASI runner as `./prog`, with a pid and a process
tab like anything else.

One platform constraint explains a lot: workerd blocks request-time WASM
compilation from raw bytes, so every module must arrive pre-compiled
through the module map. That's why Pyodide extension packages must be
declared startup modules, and why arbitrary dynamic loading fails with a
diagnostic instead of pretending.

The honest gaps, all [tracked with designs](/docs/fine-print/research/):
WASI filesystem I/O is still snapshot-plus-flush (right for one-shots,
wrong for long-running processes); stdin is EOF; no inbound sockets; and
`wasi-threads` is refused at link time on purpose — a partial
implementation would silently corrupt user data, and
[I wrote up why](https://github.com/AshishKumar4/Nimbus/blob/main/docs/wasi-threads.md).
