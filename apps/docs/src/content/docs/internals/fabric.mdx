I run every process in its own isolate because the platform gives me
nothing else. Workers isolates are capped at 128 MiB with per-invocation
CPU budgets, and Durable Objects are the only durable, strongly
consistent home — those two facts force everything above. The supervisor
schedules and owns the durable state; facets compute and are treated as
disposable.

The payoff is the OS move: if every process already owns an isolate, an
app can span several. That's how opencode runs as a serve-plus-TUI pair
joined by loopback, each half with its own budget.

<RequestLifecycle caption="A preview request and an in-session curl take the same path through the registry, and the response streams the whole way." />

Writes flow one way. Facets never own files — every mutation streams to
the supervisor through a credit pool, no credits no send, so a parallel
`npm install` physically can't flood the DO. Heavy staging stays out of
the supervisor too: opencode's ~20 MB module map is assembled outside the
DO's isolate, a rule I learned when assembling it inside crossed the
memory cap and reset the session.

## The numbers I design against

| Constraint | Cloudflare's figure | What it produced |
|---|---|---|
| Isolate memory | 128 MiB each | multi-isolate processes; staged module maps |
| DO SQLite storage | 10 GB per object | the session disk |
| CPU per invocation | 30 s default, 5 min via `limits.cpu_ms` | phased git clone, sliced checkout, fan-out installs |

A raised `cpu_ms` applies to the supervisor; facets keep the ~30 s
budget regardless, which is why long facet work is sliced into phases.
Idle costs nothing because hibernation is real — DO evicted, disk stays.

## Trust

The isolation is deliberately boring: I inherit workerd's production
isolation instead of inventing a sandbox — the same primitives Cloudflare
runs untrusted customer code on. The CSP does real work here (no runtime
`eval`, no request-time WASM compilation; code arrives through declared
module maps or doesn't run). Sessions share nothing but read-only
content-addressed caches, and loopback is session-internal. Outbound is
open by default — npm and git need it — and per-session egress policy is
an honest gap on the [research page](/docs/fine-print/research/).
