The process table lives in the supervisor DO, never in facets. A facet's
module state can vanish when workerd resets its isolate. `ps` still reads the
DO. Logs and input queues are durable and bounded, and terminals use
hibernatable WebSockets.

A keyed resident keeps `vite` or `opencode serve` warm across requests. Its
route stub resolves the worker from the loader cache. It never boots one. A
re-loaded isolate would be an empty worker with nothing listening: the silent
zombie this rule forbids. If the facet is gone, the stub fails loudly. An OOM
in a facet returns a clean, catchable RPC error, so the session survives.

The supervisor stages a big app with a small spec: argv, env, and a VFS
snapshot. The Worker-Loader cache-miss path assembles the full module map
outside the DO. opencode's map is ~20 MB, and the rule comes from a live
failure: assembling that map inside the DO crossed the memory cap and reset
the session. workerd also blocks request-time WASM compilation, so WASM
enters the module map pre-compiled.

Before anything attaches, server facets pass health gates with bounded polls
and an overall budget. The opencode pair starts the server, checks it over
loopback, then attaches the TUI at `127.0.0.1:4096`. Their lifecycles are tied,
so exiting one reaps the other. The serve half is solid. The TUI attach half
renders frames on a [thin memory
margin](/docs/fine-print/capabilities/) that is still being hardened.
