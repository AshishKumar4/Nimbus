---
title: Security & isolation
description: The trust model — workerd isolation, per-session Durable Objects, scoped JWTs, and strict token hygiene.
---

Nimbus's isolation story is deliberately boring: it **inherits Cloudflare's
production workerd isolation** rather than inventing its own sandbox. What
Nimbus adds on top is session scoping, a narrow auth surface, and strict
rules about where secrets may live.

## Isolation boundaries

- **V8 isolates** are the execution boundary. Every session is its own
  Durable Object; every process is its own Worker Loader isolate. These are
  the same primitives Cloudflare runs untrusted customer code on across its
  platform — Nimbus doesn't weaken or extend them.
- **The platform's CSP does real work**: no runtime `eval`/`new Function`,
  and no request-time WASM compilation — code arrives through declared
  module maps or doesn't run.
- **Sessions don't share state.** Filesystem, processes, ports, env — all
  per-DO. Cross-session surfaces are read-only content-addressed caches
  (npm tarballs, runtime blobs in R2).
- **Loopback is session-internal.** `127.0.0.1:<port>` resolves through the
  session's own port registry; there is no cross-session network and no raw
  public TCP listener.

## The auth surface

Covered in depth in [tokens & auth](/docs/sdk/tokens/); the security
properties:

- **Scoped, tenant-pinned, expiring JWTs** (HS256, verifier ignores the
  header `alg`). Scopes, tenant/session pins, and destroy permissions are
  enforced server-side.
- **Long-lived tokens never appear in URLs.** The only URL-carried
  credential is the 90-second, single-use, `session:bootstrap`-scoped
  attach token, whose `jti` is consumed atomically — replays get 401 — and
  which is exchanged for a sid-pinned `HttpOnly` cookie and stripped by
  redirect.
- **Session cookies**: `HttpOnly`, `Secure`, `SameSite=None`, `Partitioned`
  — an explicit cross-origin-iframe posture rather than an assumption about
  third-party cookies.

## OAuth token handling

The [session agent](/docs/machine/agent/)'s Cloudflare OAuth uses
Authorization Code + PKCE. User OAuth tokens are stored **only** in
encrypted, `HttpOnly`, `Secure`, `SameSite=Lax` cookies scoped to the
session URL — Nimbus never persists user OAuth tokens in Durable Object
storage. The hosted demo keeps its internal JWTs server-side; browsers get
demo auth cookies and OAuth cookies, never internal sandbox tokens.

## What to treat carefully anyway

- **The hosted demo is an evaluation surface**: no SLA, may be rate-limited
  or reset — don't put secrets or production data in it. Deploy your own
  for real workloads.
- **A session URL is a capability** on deployments that don't enforce auth:
  anyone with the URL joins the same filesystem. Enforced deployments
  require a token for `/new` and the attach exchange for `/s/<id>/`.
- **Outbound network is open by default** (fetch, `/dev/tcp`) — npm, pip,
  and git depend on it. Per-session egress policy is a recognized
  enterprise gap on the [research frontier](/docs/fine-print/research/),
  not a current feature.
