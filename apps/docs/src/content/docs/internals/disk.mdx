The diagram is most of the story; three mechanisms deserve words.

**Revisions.** Every path carries a subtree revision watermark that
changes iff that path or anything under it mutates. Runtime caches — the
Node fs snapshot, prefetch surfaces, page caches — key on it. An
unrelated write elsewhere can't evict your cache, and a stale cache can't
survive a real change. `chmod` bumps it like any other mutation, because
the mode column is real.

**Credits.** Facets mutate the disk only through the supervisor's
streaming write RPC, governed by a credit pool: a facet must hold credits
to send, and credits return as the supervisor drains. That's a hard bound
on supervisor memory no matter how many processes write at once — it's
what lets a 52,500-file `npm install` or an 84,000-file checkout land
inside a 128 MiB isolate. Bulk writes stage into a content generation
and publish atomically, so a crashed install never leaves a half-written
tree visible.

**The bridge.** Runtimes read and write through one contract,
`RuntimeFsBridge` — stat, ranged read/write, truncate, directory and
symlink ops, `revision(path)`, and event subscription. It's stateless on
purpose: no server-side handle state means it stays correct across
supervisor hibernation. Node's async fs rides it live, including files a
child process created after the facet started. Node's sync fs serves
from a bounded snapshot plus a local write cache, revision-invalidated —
a documented optimization. Python, Ruby, and WASI one-shots still use
snapshot-plus-diff-flush; moving their long-running I/O onto the live
bridge is [active work](/docs/fine-print/research/).

The coherence rule all of this converges on: every read observes either
the latest committed revision or your own unflushed write. Conflicts fail
deterministically and loudly, never by silent overwrite.
