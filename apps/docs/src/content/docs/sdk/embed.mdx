---
title: Embed Nimbus in a Worker
description: Deploy to your own Cloudflare account, then mint sandboxes programmatically or drop the terminal into React.
---

```bash
npx create-nimbus-app my-nimbus-worker && cd my-nimbus-worker && npm install
CLOUDFLARE_ACCOUNT_ID=<account-id> npx @nimbus-sh/cli setup cloudflare --name my-nimbus-worker
npx wrangler secret put JWT_SECRET
npx wrangler deploy
```

That's the whole deploy. `setup cloudflare` creates the R2 buckets Nimbus
binds to and seeds the Python, Ruby, and clang runtimes. If Wrangler
reports R2 error `10042`, enable R2 once in the dashboard for that
account and rerun. The scaffolded Worker is a few lines around
`createNimbusHandler` from `@nimbus-sh/sdk/worker` —
[configure the handler](/docs/sdk/handler/) covers every option.

The same SDK handle then works two ways — colocated through your own DO
binding, or remote against any authenticated deployment:

```ts
import { Nimbus } from '@nimbus-sh/sdk';
import { defineNimbusConfig } from '@nimbus-sh/config';

const config = defineNimbusConfig({
  sandboxes: {
    default: {
      root: '/home/user',
      runtimes: { preinstall: ['python'], onDemand: true, allow: ['node', 'npm', 'git', 'python', 'shell'] },
    },
  },
});

const box = Nimbus.fromEnv(env, config).sandbox('job-123', { tenant: 'acme', subject: 'agent' });
// or: Nimbus.connect({ endpoint, token, config }).sandbox('job-123')
const result = await box.exec('python -c "print(2 + 2)"');
```

The profile is a real policy boundary — `runtimes.allow` and the
preinstall/on-demand flags are enforced before any RPC. For agent
harnesses, `box.tools({ namespace: 'sandbox' })` exposes the whole
sandbox as a Proteus-style tool provider, and `@nimbus-sh/sdk/flue`
adapts it to Flue's sandbox contract.

## From React

`@nimbus-sh/react` renders the terminal as an iframe around the session
shell — your page's JS never touches the WebSocket:

```tsx
import { NimbusTerminal } from '@nimbus-sh/react';

<NimbusTerminal endpoint="https://my-nimbus.workers.dev" token={jwt} tenant="acme" sub="alice"
  onReady={() => console.log('attached')} style={{ height: 500 }} />
```

`useNimbusSession` is the same thing headless — it returns
`{ sessionId, ready, error, attachUrl }`, driven by the shell's
`nimbus:ready` / `nimbus:error` postMessages, so you can frame the iframe
yourself.

One scope note: Nimbus is a Worker/DO/WASM sandbox, not a Linux VM — the
boundaries are in [the fine print](/docs/fine-print/capabilities/). The
hosted demo runs from
[`apps/hosted-demo`](https://github.com/AshishKumar4/Nimbus/tree/main/apps/hosted-demo),
the same embedder shape any external project ships.
