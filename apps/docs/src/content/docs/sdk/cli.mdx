`@nimbus-sh/cli` ships two bins: `nimbus` (the command surface below) and
`create-nimbus-app` (the scaffold). Everything is long-flag only; there are
no interactive prompts.

## Command reference

| Command | Flags / args | Needs |
|---|---|---|
| `nimbus token mint` | `--tenant <t>` (required), `--sub <s>`, `--ttl <sec>`, `--scopes <a,b>`, `--sid <id>` | `JWT_SECRET` env. Prints the JWT to stdout |
| `nimbus token verify <token>` | positional token | `JWT_SECRET` env. Prints the claims as JSON |
| `nimbus session new` | `--endpoint <url>`, `--token <jwt>` | POSTs `/new`, prints the session id from the redirect |
| `nimbus runtime sync` | `--bucket <name>`, `--runtimes <a,b>`, positional `runtime[@version]…` | `CLOUDFLARE_ACCOUNT_ID` env |
| `nimbus runtime list` | — | Shows staged runtimes |
| `nimbus setup cloudflare` | `--name <worker>` (required), `--bucket-prefix`, `--runtime-bucket`, `--skip-runtimes` | `CLOUDFLARE_ACCOUNT_ID` env |
| `nimbus init [directory]` | delegates to the scaffold | — |

Environment fallbacks: `session new` reads `NIMBUS_ENDPOINT` (default
`http://localhost:8787`) and `NIMBUS_TOKEN` when the flags are absent, so a
deploy-then-smoke loop needs no repeated flags:

```bash
export NIMBUS_ENDPOINT=https://my-nimbus.workers.dev
export NIMBUS_TOKEN=$(JWT_SECRET=… nimbus token mint --tenant acme --scopes session:create,session:attach)
nimbus session new
```

## The runtime cache: shared or BYOA

Python, Ruby, and clang arrive as runtime blobs from an R2 bucket, the
runtime cache. `buildNimbusWranglerConfig`'s `runtimeCache` option picks
where that bucket lives:

- `'shared'` (default): bind to the standard account-local bucket name
  `nimbus-runtime-cache-public`, which `nimbus setup cloudflare` creates
  and seeds for you.
- `'byoa'`: bring your own artifacts. Binds `${r2BucketPrefix}-runtime-cache`
  instead, and you stage the blobs yourself:

```bash
CLOUDFLARE_ACCOUNT_ID=<id> nimbus runtime sync --bucket my-worker-runtime-cache python clang
nimbus runtime list
```

`runtime sync` without `--bucket` targets the canonical bucket; with
`--bucket` it stages into yours. An object form
`{ mode: 'byoa', bucket: 'custom-name' }` overrides the bucket name
entirely.

## Programmatic use

The CLI's real logic is exported from the package root, so provisioning
can run inside your own tooling: `mintToken`, `syncRuntimes`,
`setupCloudflare`, and `scaffold`.
